# لوحة تحكم المتاجر

داشبورد واحد لكل المتاجر اللي عندها بوت. كل متجر بيشوف بياناته بس، وإنتي (إدارة المنصة) بتشوفي كل المتاجر.

**التقنيات:** Next.js 16 · TypeScript · Supabase (قاعدة البيانات وتسجيل الدخول) · Tailwind CSS 4 · Zod

## الأقسام

| الصفحة | فيها إيه |
|---|---|
| الطلبات | فلترة حسب الحالة، تفاصيل الطلب، تأكيد ← توصيل ← تسليم، إلغاء بسبب، «نسخ للتوصيل»، واتساب واتصال، طلبات التعديل من البوت |
| المحادثات | «محتاجة رد» بسبب التحويل، المحادثة كاملة، «أنا برد» (البوت بيسكت 12 ساعة)، رجوع للبوت |
| المنتجات والمخزون | بحث، «خلص / رجع»، إخفاء عن البوت، المنتجات اللي فيها مشاكل، الكميات وحركة المخزون (توريد، بيع من المحل، جرد) |
| الإحصائيات | محادثات، طلبات، قيمة، تحويل، أكثر المنتجات، بحث بدون نتيجة، أسباب التحويل |
| الإعدادات | بيانات المتجر ولونه، السياسات، مناطق التوصيل، شركات التوصيل، البوت والقنوات، الفريق |
| إدارة المنصة (`/admin`) | كل المتاجر بأرقامها وتكلفة الذكاء الاصطناعي، إنشاء متجر، الاشتراك |

## التشغيل

1. جهّزي قاعدة البيانات بالملفات اللي في [`supabase/`](supabase/README.md).
2. انسخي `.env.example` لملف `.env.local` وحطي فيه Project URL والـ publishable key من Supabase.
3. شغّلي:

```bash
npm install
npm run dev        # على http://localhost:3000
npm run check      # lint + typecheck + tests
```

## الرفع على Vercel

1. Vercel ← Add New Project ← اختاري الريبو.
2. Environment Variables: `NEXT_PUBLIC_SUPABASE_URL` و `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`.
3. Deploy.
4. في Supabase ← Authentication ← URL Configuration: حطي رابط Vercel في **Site URL**.

## الأمان

- **الصلاحيات في قاعدة البيانات نفسها (RLS):** حتى لو في غلطة في كود الواجهة، قاعدة البيانات ما بترجعش بيانات متجر لحد مش منه. اتختبرت بـ 30 حالة على Postgres.
- **مفتاح الـ service_role ما بيدخلش الداشبورد خالص.** الداشبورد بيشتغل بصلاحيات المستخدم اللي داخل بس، والمفتاح ده مكانه n8n وبس.
- **كل Server Action بتتأكد من جديد** مين المستخدم وإنه عضو في المتجر (`src/lib/auth/dal.ts`)، وبتفحص كل المدخلات بـ Zod، وما بتثقش في أي رقم جاي من المتصفح.
- **رسائل الخطأ:** المستخدم بيشوف رسالة واضحة بالعربي، وتفاصيل قاعدة البيانات بتفضل في الـ logs على السيرفر.
- **Content-Security-Policy** بـ nonce جديد مع كل طلب، والسكربتات والاتصالات مسموحة بس لنفس الموقع ولـ Supabase. ومعاها HSTS و`X-Frame-Options: DENY`.
- **الحماية من التحويل لموقع تاني:** رابط `?next=` بعد تسجيل الدخول ما بيوديش برّه الموقع.
- **الطلب اللي اتغيّر في نفس اللحظة:** لو اتنين غيّروا نفس الطلب في نفس الوقت، التغيير التاني بيترفض بدل ما يكتب فوق الأول.
- **تسجيل الدخول:** ما فيش تسجيل عام، والحسابات بتتعمل من إدارة المنصة.

## هيكل الكود

```
src/
  proxy.ts                  ← أول بوابة: الجلسة + CSP + تحويل لصفحة الدخول
  lib/
    auth/dal.ts             ← مين المستخدم وإيه صلاحيته (المكان الوحيد)
    supabase/               ← عملاء Supabase + أنواع الجداول
    actions.ts              ← نتيجة الـ actions ورسائل الأخطاء
    validation.ts           ← قواعد Zod المشتركة
  features/<القسم>/
    queries.ts              ← قراءة البيانات (سيرفر بس)
    actions.ts              ← التعديلات (Server Actions)
    components/             ← واجهة القسم
  app/                      ← الصفحات
  components/ui/            ← أزرار، حقول، بطاقات
supabase/                   ← SQL قاعدة البيانات
tests/                      ← اختبارات
```

## لما تتغيّر قاعدة البيانات

بعد أي تعديل في SQL، طلّعي الأنواع من جديد عشان TypeScript يعرف الأعمدة الجديدة:

```bash
npx supabase gen types typescript --project-id <project-ref> > src/lib/supabase/database.types.ts
```
